# Bulls and Cows — Design

## 1. Архитектура

Проект разделён на три части:

- `src/core/` — игровая логика без DOM и localStorage.
- `src/storage/records.ts` — проверка, сортировка и сохранение рекордов.
- `src/ui/app.ts` — создание интерфейса и обработка событий пользователя.

`src/main.ts` запускает приложение.

Интерфейс создаётся через `document.createElement`, `textContent`
и `append`. Методы `innerHTML` и `insertAdjacentHTML` не используются.

## 2. Структуры данных

### Секрет и попытка

Секрет и попытка представлены строками. Это сохраняет ведущий ноль
и позволяет использовать шестнадцатеричные символы.

Перед проверкой буквы приводятся к нижнему регистру.
Поэтому `A` и `a` считаются одинаковыми символами.

### Состояние игры

Тип `GameState` содержит:

- длину секрета и основание системы счисления;
- секрет;
- время начала и завершения;
- массив истории попыток.

Типы состояния и попыток используют `readonly`.

`submitGuess` не изменяет переданное состояние. При принятии попытки
создаются новый объект состояния и новый массив истории.
Неправильная или повторная попытка возвращает прежнее состояние.

### Set

В `isValidGuess` используется `Set` для обнаружения повторяющихся цифр.

В `evaluateGuess` используется `Set` символов секрета для проверки
наличия цифры независимо от её позиции.

### Map

В `countPossibleSecrets` используется `Map<string, number>`.

Ключ имеет вид `length:base`, поэтому результаты для разных настроек
хранятся отдельно.

### Рекорды

Рекорд содержит число попыток, время в миллисекундах,
длину секрета и основание.

Для каждой комбинации настроек используется отдельный ключ:

`bulls-and-cows:records:<base>:<length>`

Хранятся десять лучших результатов.

## 3. Алгоритмы

### createDigitValidator

Функция выбирает допустимый алфавит для заданного основания
и возвращает функцию проверки одного символа.

Возвращаемая функция используется в `isValidGuess`
и при фильтрации ввода в интерфейсе.

### isValidGuess

Проверка выполняется в три этапа:

1. Длина строки должна совпадать с выбранной длиной секрета.
2. Каждый символ должен пройти проверку `createDigitValidator`.
3. Размер множества символов должен совпадать с длиной строки.

Регистр нормализуется до проверки повторов.

### evaluateGuess

Функция получает корректные строки одинаковой длины без повторов.

Первый `filter` выбирает цифры, совпадающие с секретом
на той же позиции. Их количество — число быков.

Второй `filter` выбирает цифры, присутствующие в множестве секрета,
но находящиеся на другой позиции. Их количество — число коров.

Одна цифра не учитывается одновременно как бык и корова.

### generateSecret

Создаётся массив допустимых цифр.

На каждом рекурсивном шаге:

1. Выбирается случайный индекс.
2. Выбранная цифра добавляется к секрету.
3. Через `filter` создаётся новый массив без выбранной цифры.
4. Выполняется следующий шаг.

Повторы невозможны, потому что выбранная цифра исключается
из дальнейшего выбора. Ведущий ноль разрешён.

Источник случайности передаётся аргументом `random`.
По умолчанию используется `Math.random`.
В тестах передаётся предсказуемая функция.

### countPossibleSecrets

Используется рекуррентная формула:

P(base, length) = base × P(base - 1, length - 1)

Базовый случай:

P(base, 0) = 1

Если длина превышает количество доступных цифр,
результат равен нулю.

Перед вычислением проверяется кеш. Вычисленный результат
сохраняется в `Map`.

### Сортировка рекордов

`rankRecords` создаёт копию входного массива.

Результаты сортируются:

1. По числу попыток по возрастанию.
2. При равенстве — по времени по возрастанию.

После сортировки остаются первые десять записей.

## 4. Сложность алгоритмов

Обозначения:

- n — длина секрета или попытки;
- b — количество доступных цифр;
- k — количество сохранённых в кеше пар параметров.

Для Set и Map предполагается среднее постоянное время доступа.
Арифметические операции рассматриваются как O(1)
для используемых небольших чисел.

### createDigitValidator

Подготовка алфавита требует O(b) времени и памяти.

Проверка одного допустимого по длине символа через `includes`
требует O(b) времени в худшем случае.

В приложении b не превышает 16.

### isValidGuess

Нормализация строки и создание Set требуют O(n).

Проверка каждого символа через `includes` требует до O(b),
поэтому общая оценка времени — O(n × b).

Дополнительная память — O(n + b).

При ограниченном алфавите приложения время можно считать O(n).

### evaluateGuess

Создание массивов и Set, а также два прохода `filter`
требуют O(n) времени в среднем.

Дополнительная память — O(n).

### generateSecret

Каждый из n шагов создаёт новый массив оставшихся цифр
через `filter`, обрабатывая не более b элементов.

Время — O(n × b).

Консервативная верхняя оценка дополнительной памяти — O(n × b):
рекурсивные вызовы могут удерживать массивы предыдущих шагов.
Глубина стека — O(n).

Эта реализация выбрана ради простоты и отсутствия изменения
массивов на месте; в игре n не превышает 6, а b — 16.

### countPossibleSecrets

Первое вычисление без подходящих кешированных результатов
требует O(n) времени и O(n) памяти стека.

Вызов для уже сохранённой пары требует в среднем O(1) времени.

Общая память кеша — O(k).

## 5. Принципы организации кода

### Разделение ответственности

`evaluateGuess.ts` считает результат попытки.
`gameState.ts` управляет переходами состояния.
`records.ts` работает с рекордами.
`app.ts` отвечает за интерфейс и события.

### Повторное использование

`createDigitValidator` используется и в проверке попытки,
и в фильтрации пользовательского ввода.

Правила допустимых символов не дублируются в интерфейсе.

### Неизменяемость

`submitGuess` создаёт новую историю через spread-синтаксис.

`rankRecords` сортирует копию массива.

`generateSecret` создаёт новый массив доступных цифр
на каждом шаге.

### Явные зависимости

Источник случайности передаётся в `generateSecret`.

Время передаётся в `createGame` и `submitGuess`.

Хранилище передаётся в `loadRecords` и `saveRecord`,
поэтому тесты могут использовать хранилище в памяти.

### Контроль побочных эффектов

DOM, таймер и получение текущего времени находятся в UI.

Чтение и запись рекордов находятся в модуле хранения.

`countPossibleSecrets` использует внутренний изменяемый кеш,
но возвращаемый результат зависит только от аргументов.

`generateSecret` с Math.random не является детерминированной;
инъекция random позволяет предсказуемо тестировать алгоритм.

### Обработка ошибок

Некорректные параметры генерации отклоняются.

Повреждённые данные рекордов проверяются при чтении.

Ошибки localStorage обрабатываются без завершения игры.

Повторная попытка не добавляется в историю.

## 6. Проверки

Автоматические тесты проверяют:

- допустимые символы разных систем счисления;
- длину попытки и отсутствие повторов;
- независимость от регистра;
- подсчёт быков и коров;
- генерацию уникального секрета;
- рекурсивный подсчёт вариантов;
- переходы состояния и неизменяемость истории;
- сохранение и сортировку рекордов;
- обработку повреждённых данных и ошибок записи.

Команды:

- `npm run typecheck` — проверка типов.
- `npm run lint` — проверка ESLint.
- `npm run format:check` — проверка форматирования.
- `npm test` — запуск тестов.
- `npm run build` — сборка приложения.

Перед коммитом Husky запускает lint-staged.
Перед отправкой изменений Husky запускает тесты.
